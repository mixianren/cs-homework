项目框架 —— 医院门诊预约与智能导诊系统
======================================

一、分层
--------

  界面层  menu/                    显示信息、接收输入
     |
  业务层  service/                 业务逻辑与计算
     |
  数据层  data/ file/ model/ ds/   DataStore 统一持有数据

界面层不做业务判断，业务层不读写屏幕，业务模块之间互不调用、都只依赖
DataStore。这样换界面不影响业务。

二、目录与职责
--------------

  ds/       数据结构
              SeqList.h        顺序表（模板）       科室/医生/症状等表
              LinkedList.h     双向链表（模板）     预约记录
              Queue.h          循环队列（模板）     候诊排队
              HashTable.h/.cpp 哈希表              按编号、按名称的索引
              Sort.h/.cpp      排序 + 二分查找      导诊结果排序

  model/    Entity.h       六个实体结构体 + 状态常量
  data/     DataStore.h    数据仓库：主表 + 索引 + 排班网格 + 号源操作
  file/     FileLoader.h   文本文件加载 + 行解析
  service/  Triage.h       智能导诊（加权二部图）
            DoctorQuery.h  医生查询 + 排班号源
  menu/     Menu.h         界面层
  src/      main.cpp       程序入口
  tests/ tools/ files/     自检、数据生成器、测试数据
  util/     Console.h      控制台工具（显示宽度、输入校验）
ds/ 下 SeqList、LinkedList、Queue 只有 .h —— 模板类的实现必须与声明放
同一文件，否则编译时看不到函数体，链接阶段会报 undefined reference。
HashTable、Sort 不是模板，拆成 .h + .cpp。

当前完成情况：ds/ 五个容器与 model/Entity.h 已完成；其余模块只有头文件
与说明，未实现。

三、数据结构选用
----------------

  科室/医生/症状管理   SeqList + HashTable
      顺序表存本体，哈希表按编号索引

  智能导诊             加权二部图（邻接表）
      题目实现提示要求的模型

  排班与号源           二维数组 + HashTable
      两个下标对应两个维度，定位 O(1)

  预约记录             LinkedList
      取消要从中间删，链表 O(1)

  候诊排队             循环队列
      先到先服务

  导诊结果排序         quickSort
      按匹配度降序

数据量很小（科室 10、医生 30、症状 59），选型考虑的不是性能，而是哪种
结构最自然地表达这个业务。

四、五个容器
----------------

题目不能用类库，所以自己实现。顺序表、链表、循环队列写成模板类（要装
多种实体类型），哈希表和排序写成非模板。

SeqList 顺序表
  结构      堆数组 + length + capacity
  关键设计  初始容量 8，按 2 倍扩容。禁止拷贝（浅拷贝会重复释放），
            必须有移动（扩容搬移、嵌套使用需要）
  复杂度    尾插 O(1) 均摊；下标访问 O(1)；插入/删除/查找 O(n)

LinkedList 双向链表
  结构      带头结点哨兵
  关键设计  头结点使"首位置插入删除"与"中间插入删除"代码一致；
            删除只改两个指针
  复杂度    删除 O(1)；查找 O(n)

HashTable 哈希表
  结构      除留余数 + 链地址
  关键设计  键取余 1009；取质数是为了分散；固定容量不扩容（数据量已知）
  复杂度    平均 O(1)，最坏 O(链长)

Queue 循环队列
  结构      环形数组
  关键设计  一个位置区分队空队满：队空 front==rear，
            队满 (rear+1)%capacity==front
  复杂度    入队出队 O(1)

Sort 排序
  结构      函数指针传比较规则
  关键设计  一套规则支持升降序；快排三者取中选基准，避免有序数据退化
  复杂度    快排平均 O(n log n)；二分 O(log n)

要分清两点：链表的删除是 O(1)，查找仍是 O(n)；哈希表不是为性能而用
（30 人遍历也只有 30 次比较），用它是为了让"按编号查找"的逻辑只有一处。

五、智能导诊的数据结构
----------------------

加权二部图：症状与科室为顶点，关联强度为边权。左部 59 条症状，右部
10 个科室，88 条带权边。用邻接表存（稀疏图，矩阵会有一大片零元素），
在 DataStore 里是 SeqList< SeqList<SymptomDeptLink> >。

  对选中的每个症状 s，取它的关联表，对每条边 (科室 d, 权重 w)：
      score[d] = score[d] + w

  match[d] = score[d] / 选中症状数 × 100%
  按 match 降序，得分相同按科室编号升序；取前 5 名

选中"牙痛、头痛、发热"的结果：

  科室        累加                  score   match
  口腔科      牙痛 0.90             0.90    30%
  神经内科    头痛 0.85             0.85    28%
  儿科        发热 0.80             0.80    27%
  内科        头痛 0.25 + 发热 0.25 0.50    17%
  外科        发热 0.20             0.20    7%

局限：累加式对关联面广的科室有利。选中"头痛、发热、咳嗽"时儿科 43%、
内科 40% —— 内科命中 3 个症状里的 3 个，每个权重都不高但加起来就追到
第二。这也是必须把综合科室权重压得很低的原因。

六、排班的二维数组
------------------

日期和时段合成一个下标就变成二维：

  int Schedule::slotIndex(int day, int slot)
  {
      return day * SLOT_COUNT + slot - 1;
  }

day 取 0~6、slot 取 1~2，合起来 0~13 共 14 个时段。网格下标是
"医生编号 × 14 + slotIndex"，值是该排班在主表中的下标（-1 表示不排班），
访问 O(1)。

号源的检查和扣减写在同一个函数里，中间不插入其他操作，调用方只能靠
返回值判断成败。归还要保证 booked 不会变负，所以必须拒绝重复取消。

七、数据实体
------------

六个结构体，三条约定：字符串用定长字符数组（不用 std::string，赋值即
拷贝不需管内存）；实体之间只存编号不存指针（顺序表扩容时指针会失效）；
结构体保持纯数据。

Department 科室
  字段    id、name[32]、floor、room[16]、location[128]、symptoms[128]
  说明    symptoms 留空 —— 常见症状已记在关联表里，再存一份就有两个
          数据源要同步

Doctor 医生
  字段    id、name[32]、deptId、title、goodAt[128]、rating、roomId[16]
  说明    goodAtContains 用子串匹配，查"高血压"能命中"高血压,冠心病"

Symptom 症状
  字段    index、name[32]、bodyPart
  说明    关联关系不放这里 —— 一条症状可关联多个科室

Schedule 排班
  字段    doctorId、day、slot、capacity、booked
  说明    剩余号源不存字段，算出来。多存一个就有三个数要同步，
          忘了更新会出现"显示有号但约不上"

Patient 患者
  字段    id、name[32]、phone[16]
  说明    预约记录不内嵌 —— 条数会变化，内嵌链表会破坏纯数据

Appointment 预约
  字段    id、patientId、doctorId、deptId、day、slot、seqNo、status、
          symptom[32]
  说明    deptId 冗余一份便于按科室统计，加载时由医生反查填入

状态用 const int 而非 enum —— 这些值要写进文本文件、也要和用户输入
比较，用 const int 可直接当整数用。
